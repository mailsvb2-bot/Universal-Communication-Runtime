# Applicable chaos-scenario evidence

Status: **implemented local/reference boundaries only**.

This matrix indexes executable chaos evidence for capabilities that actually exist in the Rust reference runtime. It does not create placeholder Relay/DNS/network implementations or crash hooks merely to make the Canon checklist appear complete. Phase 29 adds real Prepared SFU routing and therefore adds SFU failure evidence in the same change. A scenario becomes required against a new real boundary in the same change that introduces or promotes that boundary.

| Packet/request duplication | canonical command ingress + SQLite | `duplicate_ingress_chaos_has_one_canonical_acceptance` | two concurrent equivalent retries produce exactly one Accepted and one Duplicate outcome | this is implemented command-ingress duplication, not a production network packet layer |

## Evidence ownership

Cross-crate scenarios live in `crates/ucr-security-tests/tests/chaos_scenarios.rs`. That crate is evidence-only: it composes public UCR APIs and must not own retry, authorization, identity, crypto, Sync, Device, or persistence policy. Provider-private storage fault injection lives with the provider: SQLite capacity exhaustion is exercised in `crates/ucr-storage-sqlite` on the store's existing private connection, then the production `CommandAcceptanceStore` path is invoked. Process-kill evidence also remains provider-private: a `#[cfg(test)]` pause exists only in test builds immediately before the real Command transaction commit, while the parent kills a separate test process. No public chaos API or parallel storage policy is introduced.

The executable scenarios deliberately assert durable/security outcomes rather than “did not crash”. New real infrastructure boundaries must extend this matrix and executable evidence before Production maturity. Phase-29 SFU evidence lives with the real `ucr-sfu` boundary rather than in a mock infrastructure crate. Phase-31 Bridge backpressure evidence likewise lives with the real `ucr-bridge` provider boundary. Existing open rows stay open until the relevant real failure can be injected without inventing a second runtime or a fake production component.
