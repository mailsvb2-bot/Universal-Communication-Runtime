# Executable Threat Simulations

Status: **required security evidence for implemented trust boundaries**.

The Canon requires threat tests to exercise the relevant boundary and failure semantics; a unit test whose name merely mentions the threat is insufficient. The dedicated `ucr-security-tests` workspace crate therefore composes public Core, Crypto, Protocol, Memory, SQLite, and Internet-route boundaries as an attacker would encounter them. These tests are executed by the ordinary workspace debug and release CI jobs.

## Scope and nonclaims

The MITM evidence now includes the real Prepared Phase-15 TCP boundary, including signing-key substitution before sink, authenticated receipt tamper rejection, bounded chunk/reassembly handling, and literal-public-IP route admission. This is not a claim of Production maturity, DNS discovery, routing failover, Relay/NAT traversal, or deployment hardening; those remain separate future boundaries.

Phase 29 now has executable compromised-SFU evidence for the real Prepared MLS-backed group-media routing boundary, including source spoof/tamper, stale-epoch, revoked-Device and permission-preflight rejection. Phase-30 Conference coordination now reuses the same SFU boundary with recipient-owned bounded subscriptions; production SFU networking/sharding are still not claimed. The compromised-Bridge scenario stays open until a real Bridge boundary exists. UCR intentionally does not add a fake Bridge solely to make a checklist green. When a Bridge or another new trust boundary is implemented, executable negative scenarios must arrive in the same maturity change rather than inheriting the evidence above.

This document is an evidence index, not a second security policy owner. Normative threat requirements remain in `THREAT_MODEL.md`; canonical authorization, identity, crypto, Device, and storage semantics remain owned by their existing specs and crates.
